# 电商文案 Agent 首版设计

> 历史版本。当前生成流程以 [营销工作流升级](2026-09-30-marketing-workflow-design.md) 为准，替代本文的单次生成、两次调用上限与无资料检索约束；其余约束保留。

日期：2026-09-30  
状态：用户已确认本文；首版已实现并完成本地验证。实际验证范围与限制见 `docs/verification.md`（相对项目根目录）。

## 1. 目标与范围

开发一个可以嵌入其他 Python 程序的电商文案 Agent，以及最简单的桌面测试应用。用户输入商品属性、商品图片和写作要求，获得相应文案。桌面应用只是核心包的调用方，不承载核心业务逻辑。

用户已确认的技术方向：Python、LangGraph、独立核心包、可替换模型适配器、Tkinter 测试界面。首次接入用户提供的 OpenAI 兼容中转站，但不固定服务地址、密钥或模型名称。

首版交付：

- 可安装、可导入的 Python 包 `ecommerce_copy_agent`。
- 同步与异步生成接口，以及脱离桌面应用的调用示例。
- OpenAI 兼容 Chat Completions 适配器。
- 基于 LangGraph 的有界生成与修正流程。
- Tkinter 桌面测试入口、示例配置、使用说明及自动化测试。

首版不包含 HTTP 服务、账号系统、数据库、联网搜索、长期记忆、批量任务、图片生成、其他协议的现成适配器和多 Agent 协作。以后可以在核心包之外添加 HTTP 服务；接入其他协议需要实现适配器，并非只更换 URL 即可。

## 2. 分层与依赖

```text
其他 Python 程序 / Tkinter 测试应用
                    ↓
      CopywritingAgent 公共接口
                    ↓
      LangGraph 状态与业务流程
                    ↓
        ModelAdapter 统一接口
                    ↓
  OpenAI Chat Completions 适配器
                    ↓
           用户配置的中转站
```

建议目录：

```text
src/ecommerce_copy_agent/
  __init__.py              公共接口导出
  schemas.py               请求、结果、配置与校验模型
  errors.py                对调用方稳定的错误类型
  agent.py                 同步与异步调用入口
  workflow.py              LangGraph 节点与条件路由
  prompts.py               文案生成与修正提示
  validation.py            本地输出检查
  adapters/
    base.py                标准模型请求、响应及适配器协议
    openai_chat.py         Chat Completions 协议转换
desktop/                   可选桌面测试入口
examples/                  无界面调用和配置示例
tests/                     核心、流程与适配器测试
```

核心包不导入 Tkinter，不创建窗口，不读取桌面控件，不要求调用方了解 LangGraph。模型协议转换只存在于适配器内部。首版使用单次调用的内存状态，不启用持久化 checkpoint。

## 3. 公共接口与数据约定

公共入口为 `CopywritingAgent`，构造时注入实现 `ModelAdapter` 的对象：

```python
agent = CopywritingAgent(model=adapter)
result = agent.generate(request)
result = await agent.agenerate(request)
```

同步与异步接口接受相同的请求类型，返回相同的结果类型。异步上下文中应使用 `agenerate`；同步入口不嵌套运行事件循环。公共数据对象支持转为字典或 JSON；字节来源的图片在 JSON 中使用 Base64 编码，本地文件来源保留路径，读取发生在生成调用时。

### 输入 `CopyRequest`

- `product`：必填商品名称；可选品类、品牌、描述和卖点；`attributes` 为可扩展的属性映射，接受字符串、数字、布尔值及字符串列表。
- `images`：可选的本地文件来源或字节来源及媒体类型。核心统一验证并读取为图片内容，再交由适配器处理；不自动访问远程图片 URL。
- `requirements`：文案类型、目标平台、人群、语气、语言、最大字符数和额外要求。文案类型和平台允许自定义文本，不用固定枚举锁死场景。

默认生成一份文案，默认语言为简体中文。文案类型提供宣传文案、商品标题、卖点描述、详情介绍和社交平台文案作为界面预设，仍允许自定义。

首版每次最多四张图片，每张不超过 10 MiB；接受 JPEG、PNG、WebP 的静态图片，并检查实际内容与类型是否匹配。不能读取或解码的图片在请求模型之前报错。

最大字符数为可选正整数：按去除首尾空白后的文案正文计算 Python 字符串长度，正文中的标点、空格和换行计数。该定义用于稳定测试，不声称等同于任一电商平台的计数规则。

### 输出 `CopyResult`

- `text`：最终文案正文，必为非空文本。
- `warnings`：需要用户注意或核实的提示；为空不代表内容经过事实认证。
- `model`：本次配置的模型名称。
- `usage`：本次所有模型请求的 token 使用量之和；任一次缺失用量时整体为 `None`，不将部分用量冒充总用量。
- `request_count`：本次实际发起的模型请求次数，用于区分直接生成与修正后生成。

返回结果不包含密钥、内部提示词、图片原始内容或框架内部状态。调用方可以直接使用 `text`，也可以序列化完整结果。

## 4. 模型接口与配置

`ModelAdapter` 定义异步 `generate(ModelRequest) -> ModelResponse` 接口。标准请求只表达文本消息和图片内容，标准响应表达模型文本、可用的 token 用量和模型标识，不暴露厂商 SDK 类型。生成参数由具体适配器的配置持有，工作流不解释或转换这些参数；这避免把某个协议的参数名称强加给未来的适配器。

适配器配置包括：

| 配置项 | 首版约定 |
| --- | --- |
| `provider` | 首版内置 `openai_chat`；其他协议由新增适配器支持 |
| `base_url` | 用户提供的 API 根地址，例如包含 `/v1` 的地址，不是完整的 `/chat/completions` 端点 |
| `api_key` | 显式传入或从环境变量读取，不放入业务请求 |
| `model` | 自由填写，不内置模型白名单 |
| `supports_images` | 显式能力配置；默认关闭，不根据模型名称推断 |
| `timeout_seconds` | 每次请求默认 60 秒，可调整 |
| 可选生成参数 | 仅传递用户明确配置的温度、输出 token 上限等参数，降低兼容风险 |

中转站与模型都可能限制图片能力。配置未声明支持图片时，含图请求在本地明确失败；声明支持但远端拒绝时，返回能力或请求错误，不能静默丢弃图片。

首版默认不要求中转站支持工具调用或严格 JSON Schema 输出。通过提示要求输出包含 `text`（非空字符串）和 `warnings`（字符串数组，可为空）的 JSON 对象，由本地解析与校验；纯文本仍属于不符合结果契约的输出，可以进入一次修正。模型输出不负责提供调用次数或用量，这些元数据由程序填充。

地址使用 HTTP 或 HTTPS，允许本地开发端点；不在 URL 中嵌入凭据，不关闭 TLS 证书验证。认证失败、模型不存在、限流和协议不兼容应转换成清晰的公开错误。

更换兼容中转站或模型只需改配置。其他程序可以直接注入自定义适配器及其配置，核心不要求使用内置的 `openai_chat` 配置加载器；增加 Responses 或厂商原生接口不需要修改工作流或商品表单，但如果需要在桌面工具中选择新协议，应相应扩展模型配置区及适配器构建入口。

## 5. LangGraph 流程

```text
校验输入 → 生成文案 → 检查结果 → 返回
                         ↓ 不通过
                      修正一次 → 再次检查 → 返回或明确失败
```

1. **校验输入**：检查商品名称、字段长度约束、图片内容、配置及能力；不符合要求时不发起网络调用。
2. **生成文案**：将商品资料、图片与写作要求传给模型。商品资料作为数据处理，不能覆盖系统规则。
3. **检查结果**：本地检查 JSON 是否可解析、结果字段类型是否正确、正文是否非空、是否满足明确的最大字符数。
4. **修正一次**：只在模型输出不符合上述可检查约束时触发；携带原始资料、上一份结果和具体检查问题。再次失败则抛出输出校验错误，不把未合格的文本作为成功结果。

单次业务调用最多发起两次模型请求。关闭底层 SDK 默认的自动重试，避免出现不可见的额外调用。认证错误、限流、超时、网络错误等直接返回错误，不进入文案修正分支。

事实边界通过提示明确：用户提供的属性是事实来源；图片只辅助描述可见特征；不得根据图片推断材质、认证、功效、价格和优惠。存在明显矛盾或信息不足时，让模型返回待核实提示，避免写成确定事实。

本地检查无法证明文案没有虚构事实，也不能可靠判定语气或全部自定义要求是否满足。首版不将提示词约束包装成可靠的自动事实审核；此类质量通过代表性样例人工评估。未提供的商品事实不允许为满足文案长度而自行补造。

## 6. 桌面测试应用

使用 Tkinter 构建单窗口表单，包含商品名称、商品属性 JSON、补充描述、图片选择与移除、文案类型、写作要求、模型配置、生成按钮、结果区域和复制按钮。

属性用 JSON 文本输入以支持任意字段；提交前显示字段格式错误。图片展示文件名即可，首版不要求缩略图。模型配置允许自由填写 API 地址和模型名，密钥输入框遮挡字符，并提供图片能力开关。

界面状态至少区分待输入、生成中、成功和失败：生成中禁用重复提交；网络调用在后台线程执行；通过 Tkinter 主线程更新控件；失败后保留输入供修改和重试。关闭窗口后不继续写入已销毁的控件。首版不提供取消模型请求的按钮。

结果正文与待核实提示分开显示，复制按钮仅复制文案正文。默认不保存密钥、商品资料、图片或历史结果；非敏感配置可通过示例配置文件或环境变量提供，不增加配置管理页面。

桌面控件使用平台原生风格，字段有明确标签，错误提供可采取的下一步。GUI 不是包安装后的必需入口；无桌面环境仍可导入和使用核心包。

## 7. 错误与敏感信息

公开错误至少区分输入错误、配置或能力错误、模型服务错误和输出校验错误。异常携带安全的错误码与说明；默认不直接转发远端完整响应体或包含 Authorization 的请求详情。

密钥不写入仓库、日志、结果对象或默认配置文件。不记录完整商品数据和图片。示例仅使用占位符与环境变量名称。模型失败时不返回预制文案冒充真实生成结果。

## 8. 验证与验收

自动化测试使用可注入的假适配器或模拟 HTTP 响应，不消耗真实模型额度：

- 无界面程序可以导入核心包，并分别使用同步和异步接口得到结构化结果。
- 非法商品输入、图片及配置在网络请求前失败。
- 正确的图文请求转换为中转站所需的 Chat Completions 格式；禁用图片能力时明确报错。
- 合格结果只调用模型一次；不合格结果最多修正一次；第二次仍不合格时明确失败。
- 对超时、认证失败、限流和无法解析的输出给出稳定错误，不发生隐藏重试。
- 替换假适配器而不改工作流即可工作，验证核心不依赖 OpenAI SDK 的消息对象。
- 错误、序列化结果及示例配置不泄露 API 密钥。

桌面手动检查表单输入、图片选择、后台生成、错误恢复与复制结果。验证条件不足时，应标记未验证项，不将代码编译通过视为界面验收。

真实中转站测试是单独的集成验证，需要用户提供地址、模型和密钥配置；密钥建议在本机环境或桌面输入。检查一条纯文本商品请求和一条含图请求，确认真实协议兼容性。未完成该检查时，只报告模拟测试和本地验证结果，不声称已经接通中转站。

## 9. 后续扩展边界

新增文案类型通常只需更改输入与提示，不必新增 Agent。新增模型协议通过适配器接入。后续人工反馈、多轮改稿、持久化或 HTTP 服务均作为独立需求，在现有公共接口周围扩展。

首版不承诺所有 OpenAI 兼容中转站都完全兼容；模型视觉能力、参数支持和返回格式需以真实服务验证为准。
